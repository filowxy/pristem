# 设计草稿：pristem 桌面端 UI 精造（第一轮）

> 依据：`anti-slop-rules.md` / `design-craft.md` / `weak-vision-protocol.md` / `templates.md`
> 状态：草稿已写，**方向与范围待用户确认**（阶段 3 闸门）。

## 理解

- **目的 / 受众 / 使用场景**：pristem 是"住在你机器上的智能体"的桌面外壳（不是 IDE 复制品）。
  受众是长时间把它开着工作的开发者；场景是夜间/暗光下的连续工作时段，眼睛长时间盯着低对比的
  灰阶小字是最真实的疲劳来源。
- **技术栈与约束**：React + Vite + Monaco + xterm；tao/wry 原生窗口（无浏览器地址栏）；
  **不得新增 npm 依赖**；离线可用（不能依赖 CDN 字体）；`DESIGN_SYSTEM.md` v1.0 是冻结的 token
  规范，token 变更必须同步文档（附录 A 是变更表）；窗口最小内尺寸 960×620。
- **不可动项**：功能行为、中文文案与信息架构、品牌资产（棱镜 / 字标 / 存在感刻度器）、
  IPC/HTTP 契约、六模式矩阵、现有 E2E 断言（如左栏 268px、活动带 176px、终端可多开等）。
- **关键假设（无人值守时采用）**：方向**沿用**现有 "darkroom instrument panel" 身份，不另起
  美学体系；本次是**在既有系统内做工艺级精造 + 骨架级局部重做**（空态主角感），
  不做全站换肤。用户若要求更大范围，按用户要求执行并记录豁免。

## 方向

- **美学方向（一句话）**：把"仪表盘读数"升级为"夜间机房里一个正在工作的存在的表面"——
  同一套身份，但**可读性先于克制**：该读的字读得清，该暗的才暗。
- **记忆点（用户会记住的那一个点）**：**副文本不再耳语**。
  现在 10px 的提示字是 2.89:1 的灰（低于 WCAG 正文 4.5:1），改后 4.86:1；
  同一时刻保持"暗房无彩底 + 单一冷白光"的克制底色不变。
- **备选方向（避免趋同 / 曾用过）**：玻璃拟态全家桶（已排除：backdrop-filter 仅用于浮层，
  不用于内容容器）、奶油杂志风（已排除：仅暖底+斜体衬线+编号，与暗房身份冲突）、
  深色科幻控制台（已排除：青色细线框 + 数字补零）。

### 圆角策略

`prefers-reduced-motion` 已有 3 处降级块。

# 第二轮：Night Foundry（温暖石墨 + 琥珀信号）

## 理解

- 目的不变：长时间开着的桌面 agent 外壳。问题不是功能，是**没有性格**：冷灰 + 白强调
  与任何 VS Code 主题不可区分。
- 约束：不新增依赖、离线可用、E2E 的几何与行为断言全部保留（左栏 268 / 右栏 360 /
  活动带 176 / 标题栏 36 / 状态栏 24 / 刻度器 23 / 会话块 24）。
- 关键假设：用户要的是**气质层面的重构**，不是重排信息架构。

## 方向

- 一句话：**夜里的铸造车间**——温暖的石墨台面，一盏琥珀色的工作灯，仪表读数用等宽字，
  标题用衬线字；不是 IDE，是一台正在工作的仪器。
- 记忆点：**琥珀只出现在「当前 / 可执行 / 存在」三件事上**（模式刻度、主按钮、发送、
  焦点环、选中行、终端页签），其余全部是带棕调的石墨灰。
- 参考：Braun / Teenage Engineering 的仪器面板（功能色只有一种，材质是暖的）、
  Dieter Rams「少而准」、胶片暗房的琥珀安全灯；不采用任何玻璃拟态或霓虹。

## Token 草案

- 表面（由深到浅，全部带棕调）：`#100E0C / #14110E / #17130F / #181512 / #1C1814 /
  #1F1A16 / #272119 / #2D261C`
- 文本：`#F2EADC / #CFC3AE / #A99B84 / #857862`（第四级只装饰）
- 信号：`--beam #E5A64C`，亮 `#F4C77C`，暗 `#B9863C`，墨 `#1A1206`
- 语义：success `#93B98D`、warn `#D9A65A`、danger `#D47A6C`、info `#8FAECB`
- 语法（Monaco 同步）：keyword `#8FAECB`、string `#A9BE8F`、number `#D9B98A`、type `#C9A9C4`
- 字体：正文 IBM Plex Sans、等宽 IBM Plex Mono、字标 Instrument Serif；眉标改琥珀暗调 + 0.18em
- 几何：半径 / 间距 / 动效全部沿用（2px 阶梯、G2 曲率、浮起层级）
- 氛围：`.app-shell` 左上角一盏极淡的琥珀径向灯（0.055），无网格、无噪点

# 第三轮：VOID（纯黑 + 中性灰 + 白信号）

## 方向

- 一句话：**一间只有黑色和一层灰的暗房**——工作面是 `#000`，面板只比黑亮一点，
  颜色不属于界面，只属于棱镜、代码和状态。
- 记忆点：**纯黑画布上的白色动作**。主按钮是一块纯白（黑字），选中是白色下划线，
  其余全部是灰阶；没有任何彩色光晕、渐变或暖色。
- 为什么不是暖色：暖石墨 + 琥珀正是当下「高级 AI 产品」的默认皮肤，用户判定更 AI 味。
  单色黑 + 白反而更像工具：Nothing / Teenage Engineering 的 OLED 面板，靠对比度和排版说话。

## Token

- 表面：`void #000000`、`rail #030303`、`chrome #060606`、`panel #0A0A0A`、
  `inset #101010`、`raised #161616`、`float #1D1D1D`；画布 = 纯黑。
- 线：`#1A1A1A / #262626 / #383838 / #5A5A5A`。
- 文本：`#F5F5F5 / #C4C4C4 / #9C9C9C / #747474`（末级仅装饰）。
- 信号：`--beam #FFFFFF`、`--beam-ink #000000`；主按钮 / 发送 / 焦点环 / 选中 / 页签全白。
- 语义：success `#7FBF8A`、warn `#D6A85C`、danger `#D06A6A`、info `#86A9C4`（仅状态）。
- 彩色只出现在三处：棱镜图标、频谱带、代码语法色。
- 几何：保留 2px 间距阶梯、G2 曲率、浮起层级与 `corner-shape` 规则。

## 线框（不变）

```
┌ titlebar 36 ─ 衬线字标 / 白色刻度 / 灰菜单 / 白描边会话块 / 搜索 ┐
├ left 268 ──── 视图切换(白色下划线) + 资源管理器                     │
├ editor #000 ─ 页签(白色顶线) / 纯黑画布 / 26px 白标题 / 纯白主按钮  │
│               / 终端(#000 + 白色页签 + 白色光标)                    │
├ right 360 ─── AI 面板(#0A0A0A + 抬起托盘 + 纯白发送)               │
└ status 24 ── 会话 / 状态块 / 语言                                   ┘
```

## 用户确认记录

- 2026-11-20：用户否定暖色版，指定「纯黑 + 一点灰」。
- 2026-11-20（同日第三次反馈）：VOID 只换色、构图没变，仍读作「同一个 UI」。本轮补上
  **结构性视觉变化**：DIN 字族、左对齐标题页、划线式搜索、直角控件、树选中白竖线。

### 第三轮补充：构图层（不只是换色）

| 元素 | 之前 | 现在 |
|---|---|---|
| UI 字族 | IBM Plex Sans → 实际回退到雅黑 | **Bahnschrift（DIN）** 优先，数字与拉丁标签变成工程字体；中文仍走雅黑 |
| 画布空态 | 居中图标 + 标题 + 描述 + 按钮（模板感） | **左对齐标题页**：40px 白规线 → 34px 标题 → 描述 → 白色主按钮 → 快捷键两列表；左边缘 `clamp(48px,10vw,168px)` |
| 搜索框 | 圆角 pill + 填充底 | **底部划线输入**，聚焦时白线，无胶囊 |
| 主按钮 / 发送 | 6px 圆角 | **3px 直角块**（控件锐利，浮层仍保留 12px G2 曲率） |
| 资源管理器选中行 | 10% 白底 | 4.5% 白底 + **2px 白竖线**（编辑器惯例，不是卡片色条） |
| 编辑器页签 | 激活页有底色 | 透明底 + **2px 白顶线**，只靠线定位 |

> 这一层才是可见的「设计」：即使把颜色改回任意主题，标题页、DIN 字族、划线搜索与直角控件
> 仍会让界面保持同一套性格。

### 第三轮补充 2：代码是唯一的彩色表面

用户反馈「IDE 的颜色被削掉了」。修正方向：**chrome 保持纯黑/灰/白，代码与终端恢复高饱和色**。
- Monaco / xterm：keyword 紫 `#C792EA`、string 青柠 `#A9E08F`、number 琥珀 `#F2A65A`、
  type 金 `#F4D06F`、function 蓝 `#7FB2FF`、variable 青 `#8FE3E0`、tag 红 `#FF8A8A`；
  选区蓝色 `#7FB2FF30`；终端 ANSI 同一套。
- 文件树图标按类型着色（代码紫 / 配置琥珀 / 脚本金 / 文档灰）。
- 这样「黑房 + 亮代码」成为真正的方向：界面无色，工作内容有色。
